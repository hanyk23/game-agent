# Project Roadmap

Updated: 2026-07-19

## Purpose

This is the source of truth for product outcome, phase status, active mainline,
and the next gate. Evidence belongs in `docs/CURRENT_STATUS.md`, resumption in
`docs/HANDOFF.md`, detailed scope in module plans, and history in
`docs/PROGRESS_LOG.md` plus immutable run artifacts.

## Product objective lock

The product is an AI agent that converts a short request into a verified,
packaged single-player vertical bullet-hell H5 game. Development prioritizes
reusable Agent subsystems and a reviewed gameplay-module library over edits for
one evaluation game. Multiplayer, networking, split-screen, PvP, and
synchronization remain outside the current scope.

### Development boundary

Phase 7 builds the reviewed required module catalog in its approved batch order:
Core library, legacy parity, then Extended library. The complete catalog scope is
user-confirmed and is not an optional evaluation-only backlog. Phase 8 later
builds model adapters, catalog projection, request binding, the isolated OpenCode
controller, admission, and bounded repair. Only after no-cost local gates pass
may an explicitly approved model call be considered.

### Phase 7 gates

1. **Coverage and ABI design — complete:** ADRs 0025-0026 fix the catalog,
   policy, versions, runtime protocols, authority, resources, and evidence.
2. **Execution foundation remediation — complete:** ADR 0026 exits have direct
   tests, isolated build evidence, and fixed-path browser regression.
3. **First vertical slice — complete:** eleven production modules compose into
   one browser-verified Graph 1.2 while the fixed path remains passing.
4. **Core library — complete:** 27 Batch 2 definitions and representative ready
   Graph 1.3 slices pass; the later legal hostile source now exists for graze.
5. **Legacy parity — active:** the ADR 0028 pre-factory ABI gate is complete.
   Admit encounter, hostile attack, actor-set combat, scoring, and outcome
   factories, then express the preserved v2 game as a resolved graph and pass
   equivalent desktop/mobile, recovery, and package gates.
6. **Extended library — required next:** Batch 4 adds dash/inertia, homing and
   non-projectile delivery, absorption/cancellation/polarity, upgrades, arenas,
   and companions.

Every module requires a strict manifest/configuration, reviewed factory, exact
reservation, unit/property and contract tests, browser evidence, and provenance.
Matching event names never prove compatibility.

## User decisions and constraints

- No paid model call is authorized. State model, purpose, call count, token
  ceiling, and estimated cost before requesting approval.
- Preserve the fixed path until modular recovery and packaging parity.
- Complete Batch 3 legacy parity and required Batch 4 without weakening ADRs
  0026-0028 or treating Batch 4 as optional.
- Do not read credentials, expand the corpus now, weaken gates, or let generated
  code edit the kernel, orchestrator, validators, tests, or existing modules.
- Do not create Git state changes without explicit request.
